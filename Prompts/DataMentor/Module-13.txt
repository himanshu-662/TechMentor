# DataMentor AI — Phase 13

# Model Training & Experimentation Engine

## PROJECT CONTEXT

You are continuing development of:

**DataMentor AI: An Intelligent Automated Data Preprocessing, Visualization & Learning Platform**

Core philosophy:

> **Automate the work, but explain the learning.**

The platform allows a learner to upload a raw dataset, understand its problems, preprocess it, engineer features, validate it, and eventually train machine-learning models.

* Phase 1 — Project Setup

* Phase 4 — Learning / Explanation Engine

* Phase 7 — Data Transformation

These existing phases must remain functional.

# PHASE 13 OBJECTIVE

Implement:

> **Model Training & Experimentation Engine**

This phase converts a validated dataset into a reproducible machine-learning training pipeline.

The system must support:

* target selection
* problem-type selection/detection
* feature selection
* training readiness validation
* train/validation/test splitting
* leakage-safe preprocessing
* baseline models
* classification models
* regression models
* cross-validation
* hyperparameter tuning
* experiment tracking
* experiment comparison
* model artifact creation
* model registry
* experiment reproducibility
* educational explanations

This is NOT a black-box AutoML system.

The learner must understand what is happening at every major training stage.

# 2. CRITICAL ARCHITECTURAL RULE

Do NOT treat preprocessing and training as independent disconnected operations.

The final trained model must contain the complete preprocessing + model pipeline.

Use Scikit-learn Pipeline / ColumnTransformer wherever appropriate.

Example:

```python
Pipeline([
    ("preprocessor", preprocessor),
    ("model", model)
])
```

This ensures that a trained model can later receive compatible raw feature input and apply the same preprocessing.

---

# 3. MOST IMPORTANT RULE — PREVENT DATA LEAKAGE

The training system MUST enforce this order:

RAW DATA
↓
SELECT FEATURES + TARGET
↓
SPLIT DATA
↓
FIT PREPROCESSORS ONLY ON TRAINING DATA
↓
TRANSFORM TRAINING DATA
↓
TRANSFORM VALIDATION DATA
↓
TRANSFORM TEST DATA
↓
TRAIN MODEL

NEVER:

RAW DATA
↓
SCALE / IMPUTE / ENCODE ENTIRE DATASET
↓
SPLIT

The application must explicitly explain this concept.

Every training experiment must record the preprocessing configuration.

# 11. CLASSIFICATION SPLITTING

For classification, support stratified splitting.

Use appropriate Scikit-learn functionality such as:

```python
train_test_split(
    X,
    y,
    stratify=y,
    random_state=42
)
```

Explain:

> Stratification attempts to preserve target class proportions across dataset splits.

Do not use stratification for ordinary regression.
