==================================================
1. CORE PRINCIPLE
==================================================

Feature engineering must follow:

ANALYZE
→ IDENTIFY OPPORTUNITY
→ EXPLAIN
→ RECOMMEND
→ CONFIGURE
→ PREVIEW
→ VALIDATE
→ USER CONFIRMS
→ CREATE FEATURE
→ VERSION
→ RECORD HISTORY
→ LEARN

Never silently create features.

Never overwrite the original dataset.

==================================================
2. SUPPORTED FEATURE ENGINEERING
==================================================

Implement:

1. Mathematical features
2. Interaction features
3. Ratio features
4. Date/time features
5. Date differences
6. Aggregation features
7. Binning
8. Boolean/indicator features
9. Frequency/count features
10. Basic text-derived features

==================================================
3. MATHEMATICAL FEATURES
==================================================

Support:

addition
subtraction
multiplication
division
absolute value
square
square root
log1p

Example:

price × quantity
→ total_price

Use a controlled expression system.

NEVER use eval() or execute arbitrary user-provided Python.

==================================================
4. INTERACTION FEATURES
==================================================

Allow:

A × B

Example:

experience × salary
→ experience_salary_interaction

Explain:
- what interaction means
- why it may help
- when it can be useful
- risk of feature explosion
- risk of overfitting

Do not automatically generate every possible interaction.

==================================================
5. RATIO FEATURES
==================================================

Support:

A / B

Example:

sales / employees
→ sales_per_employee

Handle division by zero safely.

Never silently create infinity values.

Allow a configurable policy:
- NaN
- 0
- user-defined handling

Default to a safe non-destructive behavior.

==================================================
6. DATE/TIME FEATURES
==================================================

Detect datetime columns using existing semantic typing.

Allow extraction of:

year
month
day
day_of_week
day_of_year
week_of_year
quarter
hour
minute
second

Example:

transaction_date
→ transaction_date_year
→ transaction_date_month
→ transaction_date_day
→ transaction_date_day_of_week

==================================================
7. CYCLICAL FEATURES
==================================================

Implement optional advanced cyclical encoding.

For hour:

sin_hour = sin(2π × hour / 24)
cos_hour = cos(2π × hour / 24)

For month:

sin_month = sin(2π × month / 12)
cos_month = cos(2π × month / 12)

Explain why cyclical encoding is useful.

Do not make this the default.

==================================================
8. DATE DIFFERENCES
==================================================

Allow date difference features.

Example:

approval_date - application_date
→ processing_days

Support:
- days
- hours
- minutes

Validate date columns before operation.

==================================================
9. AGGREGATION FEATURES
==================================================

Support grouped aggregations.

Example:

customer_id + purchase_amount

Generate:

customer_purchase_amount_sum
customer_purchase_amount_mean
customer_purchase_amount_median
customer_purchase_amount_min
customer_purchase_amount_max
customer_purchase_amount_count
customer_purchase_amount_std

Allow users to choose:
- grouping column
- aggregation column
- aggregation method
- new feature name

IMPORTANT:
Show a data leakage warning.

Explain that aggregations must only use information available at prediction time.

==================================================
10. BINNING
==================================================

Support numerical binning.

Methods:

Equal-width
Custom boundaries

Example:

Age:
0–17
18–30
31–45
46–60
60+

Create:

age_group

Allow custom labels.

Warn:
Binning reduces numerical detail.

==================================================
11. BOOLEAN / INDICATOR FEATURES
==================================================

Allow rules such as:

Support:

>
<
>=
<=
==
!=

Allow output as:
- boolean
- 0/1

==================================================
12. FREQUENCY FEATURES
==================================================

For categorical columns support:

Example:

city_frequency_ratio

Use actual dataset frequencies.

==================================================
13. BASIC TEXT FEATURES
==================================================

For text columns support only basic deterministic features:

Do not implement:
- embeddings
- TF-IDF
- transformers
- semantic search
- LLM processing

==================================================
14. FEATURE OPPORTUNITY DETECTION
==================================================

Analyze dataset structure and identify useful opportunities.

Examples:

Datetime column:
→ date component features

Numerical columns:
→ ratio/interactions where meaningful

Categorical column:
→ frequency feature

Group identifier + numerical column:
→ aggregation opportunity

Text column:
→ basic text statistics

Do not generate unlimited suggestions.

Keep recommendations explainable and conservative.

==================================================
15. FEATURE RECOMMENDATION
==================================================

Every recommendation must contain:

feature type
suggested feature name
source columns
formula or rule
reason
potential benefit
potential limitation

Example:

Suggested:
sales_per_employee

Formula:
sales / employees

Reason:
Normalizes sales by workforce size.

Limitation:
Requires handling zero employee counts.

==================================================
19. FEATURE EXPLANATION
==================================================

For every generated feature provide:

WHAT?
WHY?
HOW?
WHEN SHOULD I USE IT?
WHEN SHOULD I AVOID IT?
LIMITATIONS
DATA LEAKAGE RISK
ML IMPACT
INTERVIEW TIP

Example:

Why create sales_per_employee?

It normalizes sales relative to workforce size.

Potential benefit:
Organizations of different sizes can be compared more meaningfully.

Potential limitation:
Division by zero and very small denominators can create unstable values.
