==================================================
1. CORE PRINCIPLE
==================================================

Feature selection is different from feature engineering.

Feature engineering:
creates or modifies features.

Feature selection:
chooses which existing features should remain.

Use:

PROFILE
→ IDENTIFY TARGET
→ ANALYZE RELEVANCE
→ ANALYZE REDUNDANCY
→ ANALYZE VARIANCE
→ ANALYZE MISSINGNESS
→ ANALYZE STATISTICAL RELATIONSHIPS
→ ANALYZE MUTUAL INFORMATION
→ ANALYZE MODEL IMPORTANCE
→ DETECT POSSIBLE LEAKAGE
→ EXPLAIN
→ RECOMMEND
→ USER REVIEWS
→ PREVIEW
→ CONFIRM
→ APPLY
→ VERSION
→ RECORD HISTORY

Never silently remove features.

==================================================
2. TARGET COLUMN
==================================================

Require explicit target selection for supervised feature selection.

Automatically detect target type:

- regression
- binary classification
- multiclass classification
- categorical

Allow user override.

The target must never be included in the feature matrix.

==================================================
3. MISSINGNESS ANALYSIS
==================================================

Reuse Phase 3 profile information.

For each feature calculate:

missing_count
missing_percentage

Allow configurable threshold.

Example:
80%

Flag features above threshold.

Do not automatically remove them.

Explain:
High missingness may reduce usefulness, but domain context matters.

==================================================
4. CONSTANT FEATURES
==================================================

Reuse Phase 3 detection.

Flag:
- constant features
- near-constant features

Allow configurable near-constant threshold.

Show evidence.

Do not automatically remove without user confirmation.

==================================================
5. CORRELATION
==================================================

For numerical features implement Pearson correlation.

Default high-correlation threshold:

abs(correlation) >= 0.90

Make threshold configurable.

Create an interactive correlation matrix.

Clicking a pair should show:

feature A
feature B
correlation
possible redundancy explanation

Do not automatically choose which feature to remove.

==================================================
6. CORRELATION EDUCATION
==================================================

Teach:

- correlation does not imply causation
- low target correlation does not mean useless
- Pearson captures linear relationships
- nonlinear relationships may require other methods

==================================================
7. UNIVARIATE STATISTICAL TESTS
==================================================

Implement appropriate tests.

Classification:
- chi-square where appropriate
- ANOVA F-test where appropriate

Regression:
- F-regression

Return:
- score
- p-value where available

Explain:
These evaluate feature-target relationships independently.

Do not treat p-value or score as universal feature importance.

==================================================
8. MUTUAL INFORMATION
==================================================

Implement:

mutual_info_classif
mutual_info_regression

Return MI score per feature.

Explain:

Mutual information can identify nonlinear dependencies that ordinary Pearson correlation may miss.

Do not describe MI as an absolute universal importance score.

==================================================
9. VARIANCE THRESHOLD
==================================================

Implement sklearn VarianceThreshold.

Allow configurable threshold.

Show:
feature variance
threshold
flagged status

Explain:
Variance threshold is unsupervised.

A low-variance feature is not automatically useless.

==================================================
10. MODEL-BASED IMPORTANCE
==================================================

Implement tree-based model importance using:

RandomForestClassifier
RandomForestRegressor

Use the detected target type.

Return:
feature_importances_

Allow configuration of:
- n_estimators
- random_state

Use safe defaults.

Explain:
Model-based importance is model-dependent.

Do not present it as absolute truth.

==================================================
11. DO NOT CREATE A MAGIC FEATURE SCORE
==================================================

Do NOT combine every metric into a single arbitrary score.

Instead show evidence independently.

Example:

Feature:
income

Missingness:
2.1%

Variance:
High

Target correlation:
0.62

Mutual information:
0.41

Model importance:
0.31

Redundancy:
Low

Then provide a transparent recommendation with reasons.

==================================================
12. RECOMMENDATIONS
==================================================

Recommendations must be deterministic and evidence-based.

Possible recommendations:

KEEP / REVIEW / POTENTIAL REMOVAL

But do not force a decision.

Examples:

Constant feature:
Potential removal

High missingness:
Review

Highly correlated:
Review redundancy

Strong relevance:
Consider keeping

Low variance:
Review

Possible leakage:
Investigate immediately

Every recommendation must contain:
- evidence
- explanation
- limitation
- alternative action

==================================================
13. LEAKAGE DETECTION
==================================================

Detect obvious leakage patterns.

Examples:

Feature name identical or nearly identical to target.

Features containing target-like values.

Post-outcome fields where metadata/name indicates this.

Example:

Target:
loan_default

Feature:
loan_default_status

Flag:

Potential target leakage.

Do not automatically remove.

Show:

Why this is suspicious
Why leakage is dangerous
How to investigate it
