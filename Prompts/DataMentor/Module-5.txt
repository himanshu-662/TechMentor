PHASE 5 — AUTOMATED DATA CLEANING ENGINE

Project:
DataMentor AI

CORE PRINCIPLE:

DataMentor AI is a learning-first data preparation platform.

The system should never silently modify a user's dataset.

Every cleaning operation must follow:

DETECT
  ↓
EXPLAIN
  ↓
RECOMMEND
  ↓
CONFIGURE
  ↓
PREVIEW
  ↓
USER CONFIRMS
  ↓
APPLY
  ↓
COMPARE BEFORE/AFTER
  ↓
RECORD HISTORY

Phase 2, Phase 3 and Phase 4 are already implemented.

DO NOT break existing functionality.

==================================================
4. MISSING VALUE HANDLING
==================================================

Numerical strategies:

- mean
- median
- constant

Categorical strategies:

- mode
- constant

Do not automatically choose and apply a method.

Generate a recommendation based on the Phase 3 profile.

Example:

income:
missing = 8.7%
skewness = 3.82
outliers detected

Recommendation:
median

Reason:
Median is generally less sensitive to extreme values
than mean.

IMPORTANT:

Recommendation is not automatic execution.

The user must explicitly apply the operation.

==================================================
5. RECOMMENDATION ENGINE
==================================================

Create a transparent recommendation system.

Return:

- recommended method
- reason
- supporting dataset evidence
- alternatives
- educational explanation

Example:

{
  "column": "income",
  "recommended_method": "median",
  "reason": "Strong positive skew and extreme values",
  "evidence": {
    "missing_percentage": 8.7,
    "skewness": 3.82
  },
  "alternatives": [
    "mean",
    "constant"
  ]
}

Do not use an LLM for recommendations yet.

Recommendations must be deterministic and explainable.

==================================================
6. DUPLICATE HANDLING
==================================================

Detect exact duplicate rows.

Allow:

remove duplicate rows

Before applying:

Show:

- total rows
- duplicate rows
- rows after operation
- percentage affected

Example:

Before:
10,000

Duplicates:
127

After:
9,873

The user must explicitly confirm.

==================================================
7. CONSTANT FEATURES
==================================================

Allow removal of constant columns.

Example:

country:
unique values = 1

Recommendation:
Remove constant feature

Explain:

A constant feature has no variation and generally provides
little or no predictive information for ML models.

IMPORTANT:

Never automatically remove the column.

User confirmation required.

==================================================
8. PREVIEW SYSTEM
==================================================

Every operation must support preview before applying.

Create:

POST /api/datasets/{dataset_id}/cleaning/preview

Example request:

{
  "operation": "impute_missing",
  "column": "income",
  "method": "median"
}

Return:

- operation
- affected rows
- before values
- after values
- summary statistics
- explanation

For large datasets, only return a safe limited preview.

Do not send the complete dataset to the frontend.

==================================================
9. APPLY SYSTEM
==================================================

Create:

POST /api/datasets/{dataset_id}/cleaning/apply

The request must explicitly specify:

- operation
- column if required
- method if required
- confirmation

Reject invalid or incomplete operations.

==================================================
10. VALIDATION
==================================================

Before applying an operation validate:

- dataset exists
- column exists
- semantic type is compatible
- method is valid
- operation is supported
- dataset version is valid

Examples:

Do not allow mean imputation on categorical columns.

Do not allow median imputation on text columns.

Return clear educational errors.
