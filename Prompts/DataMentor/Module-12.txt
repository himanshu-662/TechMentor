You are continuing development of:

Your task is to implement **ONLY Phase 12 — Validation & Data Quality Assessment**.

---

# 1. PRIMARY OBJECTIVE

Build a version-aware, deterministic Data Validation & Quality Assessment Engine.

The engine must independently evaluate whether the current dataset version is:

- structurally valid
- complete
- unique
- valid
- internally consistent
- integrity-safe
- numerically reasonable
- categorically consistent
- temporally valid
- free from obvious data-quality issues
- free from obvious/potential leakage signals
- suitable for downstream ML preparation

Important:

Preprocessing does NOT automatically mean the dataset is good.

Validation must independently measure the resulting state of the dataset.

# 3. CRITICAL RULE

Validation must NEVER mutate the dataset.

All validation functions must be read-only.

Do not:

- fill missing values
- remove rows
- change data types
- modify categories
- remove outliers
- rename columns
- modify feature values

Validation only analyzes and reports.

# 5. SCHEMA VALIDATOR

Create:

backend/app/validation/schema_validator.py

Validate:

- column existence
- duplicate column names
- data types
- missing columns
- unexpected columns
- type mismatches
- schema changes between versions

Do not assume a type is wrong merely because it differs from an earlier version.

Explain type changes using version history when possible.

---

# 6. COMPLETENESS VALIDATOR

Create:

backend/app/validation/completeness_validator.py

Calculate:

- total missing values
- missing percentage
- missing per column
- rows containing missing values
- completely missing columns
- high-missingness columns

Make thresholds configurable.

Default rules:

- warning at 5%
- severe/error at 30%
- special handling for 100%

Do not hard-code these thresholds throughout the codebase.

---

# 7. UNIQUENESS VALIDATOR

Create:

backend/app/validation/uniqueness_validator.py

Check:

- duplicate rows
- duplicate percentage
- identifier uniqueness
- unique-value count
- constant columns
- near-constant columns

Reuse existing profiling infrastructure where possible.

---

# 8. VALIDITY VALIDATOR

Create:

backend/app/validation/validity_validator.py

Detect:

- NaN
- infinity
- invalid numerical values
- suspicious ranges
- invalid categorical values
- invalid dates

Do NOT assume universal domain rules.

Domain constraints must be configurable.

# 9. CONSISTENCY VALIDATOR

Create:

backend/app/validation/consistency_validator.py

Detect:

- capitalization variations
- whitespace variations
- spelling/category representation inconsistencies
- cross-column logical inconsistencies

Examples:

Male
male
MALE

and:

start_date > end_date

Do not automatically modify anything.

---

# 10. INTEGRITY VALIDATOR

Create:

backend/app/validation/integrity_validator.py

Support configurable:

- column relationships
- referential integrity
- range constraints
- comparison constraints

Examples:

A <= B

start_date <= end_date

quantity >= 0

If no rule exists:

return NOT_EVALUATED.

Never pretend integrity was checked without a configured rule.

# 19. ML READINESS

Possible states:

NOT_READY
INSUFFICIENT_INFORMATION

Examples of blocking conditions:

- no usable features
- missing selected target
- invalid dataset structure

- class imbalance

- potential leakage
- suspicious outliers
