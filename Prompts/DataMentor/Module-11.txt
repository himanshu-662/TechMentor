==================================================
1. CORE PURPOSE
==================================================

The purpose of this phase is to make every preprocessing change understandable.

The system must answer:

What changed?
How much changed?
Which columns changed?
Which rows changed?
Why did they change?
Which operation caused the change?
What was the statistical effect?
What should the learner understand?

Workflow:

SELECT BEFORE VERSION
→ SELECT AFTER VERSION
→ IDENTIFY DIFFERENCES
→ CLASSIFY CHANGES
→ CALCULATE METRICS
→ VISUALIZE
→ EXPLAIN
→ LEARN

==================================================

==================================================
11. OPERATION-AWARE EXPLANATIONS
==================================================

Use transformation history from previous phases.

If operation was:

Median imputation

Explain:

What changed?
Missing values were replaced.

Why?
User selected median imputation.

Evidence:
Missing count before/after.

If operation was:

IQR capping

Explain:
Values above the upper bound were capped.

If operation was:

Log1p

Explain:
Large values were compressed and distribution statistics changed.

If operation was:

Feature engineering

Explain:
New feature created from source columns.

If operation was:

Feature selection

Explain:
Selected feature subset created a new dataset version.

Do not use an LLM.

Use deterministic metadata + Phase 4 education engine.

==================================================
12. CHANGE CLASSIFICATION
==================================================

Classify changes:

EXPECTED
REVIEW
UNEXPECTED

Use deterministic validation rules.

Examples:

EXPECTED:
missing values decrease after imputation.

REVIEW:
distribution changes substantially after transformation.

UNEXPECTED:
unrelated categorical column changed during numerical transformation.

Do not make subjective judgments.
